## Status values

| Status | Meaning |
| --- | --- |
| MEASURED | A committed file or test backs the claim, and a reviewer can rerun it with the command given. |
| PROVISIONAL | Measured, but a step its pre-registered protocol requires has not run, so the figure can still change. |
| PENDING | Not measured yet. The row names what will produce the evidence. |
| GATED | A feature behind an open gate or a later milestone. It appears only as "not available yet". |
| FORBIDDEN | Sleeve never says this, in any material. |

## Rules for using the ledger

1. Use the wording in the claim column. A shorter form may drop a sentence, never a condition, and never the context the row ties to a number.
2. A PENDING claim does not appear as a present-tense fact in the README, the app or the video. The README may describe it as design, with the row's status beside it.
3. A PROVISIONAL figure carries the word "provisional" and its reason.
4. A row changes status in the same commit that adds its evidence, and that commit edits this file.
5. Every number in the README, the app or the video comes from a script in this repo that a reviewer can rerun (build contract, working rule 7). Fork figures say "fork" and give the pinned block. Mainnet figures give receipt ids.
6. The video shows only paths that have run on mainnet, and a gated feature only as gated (PRD 16).
7. Copy writes "Robinhood Chain" and "Stock Tokens" in full and capitalized, never "tokenized stocks" or "tokenized equities", and implies no partnership with Robinhood (docs/research/issuer-docs.md section 4), or with the fund sponsor or company whose mark identifies a Stock Token (D-023, row 9.30). Every holding and every receipt carries "debt security, not a share".

## Rerun commands

Each line starts from the repo root of a clean checkout:

```
cd contracts && forge test --match-path "test/unit/*"
cd contracts && forge test --match-path test/unit/LedgerMath.t.sol
cd contracts && forge test --match-path "test/fork/*"
cd contracts && FOUNDRY_OUT=out-g6 FOUNDRY_CACHE_PATH=cache-g6 forge test --match-path test/spike/G6Spike.t.sol -vv
contracts/test/spike/kernel-bytecode-check.sh
python3 scripts/calendar_vectors.py --check
python3 scripts/premium_vectors.py --check
python3 docs/disclosure/extract.py --check
scripts/hp2/.venv/bin/python scripts/hp2/run.py --out-dir /tmp/hp2 --report /tmp/hp2/HP2_RESULTS.md
scripts/hp2/.venv/bin/python scripts/hp2/verify.py
git log -- docs/HP2_PROTOCOL.md
shasum -a 256 docs/HP2_PROTOCOL.md
git grep -nE "is [A-Za-z, ]*ERC20" -- contracts/src
```

The fork and spike suites read FORK_RPC, which defaults to https://robinhood.drpc.org, and the spike and the bytecode check also call https://rpc.mainnet.chain.robinhood.com, which challenges bursts of requests (D-012). `run.py` reads only results/hp2/data and makes no network call. Without `--out-dir` and `--report` it rewrites results/hp2 and docs/HP2_RESULTS.md in place, so the line above writes to /tmp/hp2 for comparison with the committed files.
